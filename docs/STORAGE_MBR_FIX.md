# FAT32/MBR识别修复（2026-10-26）

问题：某些合法MBR分区卡加载BMP时只读LBA0即报0x34。修复仅改变 `rtl/storage/fat32_bmp_reader.v`，其他RTL和用户正在编写的memory/system接口保持原样。

## 根因

原BOOT状态只检查LBA0的部分BPB特征（11–13、17–18、22–23字节），就认定它是无分区FAT32卷。MBR引导代码区可能恰好具有这些字节。随后完整BPB或几何校验失败直接报0x34，虽然此前已缓存有效分区表，仍没有转读分区VBR。

复现镜像保持分区表、签名、真实BPB、FAT、目录和文件不变，只令LBA0字节11=0、12=2、13=1。修复前正常镜像读取1250字节/391像素成功，变体却0字节/0像素并报0x34；扇区接口和SPI引脚整链路均复现。

## 实现

- 新增MBR状态及probe_lba0标志。LBA0的局部特征只作为候选，仍须通过完整BPB和几何校验。
- 候选校验失败且缓存中存在支持的MBR分区时，进入MBR状态读取实际分区VBR。
- 转入分区VBR前关闭回退许可；若实际分区VBR损坏，继续正常报0x34，不会反复读取。
- 有效的LBA0无分区FAT32卷仍直接采用，即使其后部字节恰好像分区表，也不误跳到伪分区。

没有通过放松BPB/几何检查或屏蔽0x34来修复。0x34仍是损坏/不支持BPB的有效错误码。
