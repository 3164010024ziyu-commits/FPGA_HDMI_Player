\# 同步 FIFO 模块设计与验证



\## 1. 模块概述



`sync\_fifo` 是基于 Verilog HDL 设计的参数化同步 FIFO（First In First Out，先进先出）模块。



模块使用单一时钟完成数据写入和读取，通过读写指针及满空标志实现数据缓存与顺序管理。



本模块是 HDMI 多媒体播放系统存储子系统的基础模块。后续可用于同一时钟域内的像素数据缓存及 SDRAM 数据传输缓冲。



\## 2. 设计参数



| 参数 | 默认值 | 说明 |

|---|---|---|

| DATA\_WIDTH | 8 | FIFO 数据宽度 |

| ADDR\_WIDTH | 4 | FIFO 存储地址宽度 |

| FIFO 深度 | 16 | 由 2^ADDR\_WIDTH 决定 |

| 时钟 | 单时钟 | 读写共用 Clk |

| 复位 | 低电平有效 | Reset\_n |



FIFO 的数据宽度和深度均可通过参数调整。



\## 3. 模块接口



| 信号 | 方向 | 功能 |

|---|---|---|

| Clk | input | 系统时钟 |

| Reset\_n | input | 低电平有效复位 |

| wr\_en | input | 写入请求 |

| wr\_data | input | 写入数据 |

| full | output | FIFO 满标志 |

| rd\_en | input | 读取请求 |

| rd\_data | output | 读取数据 |

| rd\_valid | output | 读取数据有效标志 |

| empty | output | FIFO 空标志 |



\## 4. 设计原理



\### 4.1 存储结构



FIFO 使用参数化存储数组保存数据。



读指针 `rd\_ptr` 指向下一个待读取的位置，写指针 `wr\_ptr` 指向下一个待写入的位置。



读写指针均采用 ADDR\_WIDTH+1 位，其中低位用于存储器寻址，最高位用于辅助判断 FIFO 的满状态。



\### 4.2 空满判断



当读指针与写指针完全相等时，FIFO 为空。



当读写指针的低 ADDR\_WIDTH 位相等、最高位不同时，FIFO 为满。



这种方法可以区分读写指针绕回后出现的满状态与空状态。



\### 4.3 读写控制



仅当 `wr\_en=1` 且 `full=0` 时，FIFO 执行有效写入操作。



仅当 `rd\_en=1` 且 `empty=0` 时，FIFO 执行有效读取操作。



当读取成功时，`rd\_valid` 置为有效，并通过寄存器输出读取的数据。



模块允许在 FIFO 非满、非空时同时读写。



当前实现不支持在已满状态下通过同周期读取直接腾出位置并同时写入，也不支持在已空状态下同周期写入并立即读出新数据。



\### 4.4 复位



复位时，读写指针、读取输出和读取有效标志恢复初始状态。



存储数组本身不进行逐项复位。复位后 FIFO 通过指针状态表示为空，旧存储内容不被视为有效数据。



\## 5. ModelSim 功能验证



使用 ModelSim 对 FIFO 进行了功能仿真。



已验证的主要场景包括：



1\. FIFO 连续写入直至满状态。

2\. FIFO 连续读取直至空状态。

3\. FIFO 数据先进先出顺序。

4\. 满状态下的写入阻止。

5\. 空状态下的读取阻止。

6\. 读写同时进行。

7\. 读写指针绕回。



上述场景已通过当前 Testbench 的仿真观察。



仿真文件：`tb/memory/sync\_fifo\_tb.v`



说明：当前验证主要基于手工编写的测试激励及波形检查，尚未建立完整的自动化回归测试体系。



\## 6. 安路 TD 综合验证



使用 Anlogic TD 6.2.1，对 EG4S20BG256 目标器件进行了逻辑综合。



已记录的综合结果：



| 资源类型 | 使用数量 |

|---|---|

| LUT | 37 |

| 普通寄存器（REG） | 10 |

| 输出寄存器（OREG） | 9 |

| BRAM | 0 |



本次小容量 FIFO 的存储逻辑采用片内分布式资源实现，并未使用专用 BRAM。



上述数据属于当前参数配置下的综合统计，不代表所有 FIFO 深度和数据宽度的资源消耗。
