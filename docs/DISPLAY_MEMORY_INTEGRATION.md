# display / memory 对接与双帧缓存

更新：2026-10-28。

## 已实现的连接

`hdmi_player_top` 已例化实际 `hdmi_tx_display`。Storage 的 RGB888 数据经过原有 50 → 125 MHz 异步 FIFO 写入 SDRAM；新增读控制器从前台帧缓存取数，经 2048×24 位异步 FIFO 和两字输出预取队列送入 25 MHz 像素域。当前系统启用图像显示，音频和 OSD 在该顶层实例中关闭；显示组件内的相应实现仍保留。

显示时序为 640×480、每行 800 拍、每帧 525 行。实际导入 PLL 输出是 25 MHz 像素时钟和 125 MHz 串行时钟，按此计算帧率约 59.52 Hz。没有将文档中的 25.175 MHz 当作当前实际时钟。SDRAM 的 125 MHz / 180° PLL 配置未改动。

`read_RAM.pix_req` 现在只在有效显示区拉高，每行恰好 640 次、每帧 307200 次；原来每行额外两次请求会使线性 FIFO 错位，已移到 FIFO 适配器内部独立预取。`clk_wize` 导出 `extlock`，显示组件锁定后在像素域释放复位，并向 memory 输出 `pix_reset_n`。

## 两块帧缓存的含义

SDRAM 应用地址是 **32 位字地址**，每个字保存 `{8'b0, RGB888}`，即一个像素。默认布局如下：

| 缓存 | 起始字地址 | 容量 |
| --- | --- | --- |
| 槽 0 | `B = frame_base_addr` | 307200 字 |
| 槽 1 | `B + 307200` | 307200 字 |

合计 614400 字、2457600 字节，使用封装 SDRAM，完整图像不放在片上 RAM。`B` 必须四字对齐，且 `B + 614400 <= 2097152`。第一张有效图片固定缓存池基址，直到整个 memory 复位；后续请求保持同一个 `frame_base_addr`。memory 自动选择后台槽，外部不再逐张手动指定前后台地址。

1. 初始没有有效前台，HDMI 输出黑色；槽 0 可写。
2. Storage 发送帧描述和像素；writer 完成最后四字并等待下游排空。
3. 写完成的槽进入待发布状态，`frame_write_ready=0`，此时不能覆盖它。
4. `frame_sync` 在消隐期第 480 行整行保持高电平。显示 FIFO 在这一行清空；reader 完成已接受的整组读后停止。没有在途读时，将待发布槽切为前台。
5. `frame_sync` 下降后重新预取下一幅完整光栅；原前台槽成为下一张图的后台槽。

因此“写完成”和“开始显示”是两个时间点。只有两块缓存，待发布帧切换前不会接收第三张图。写入错误只丢弃后台帧，保留已有前台；清理时等待已接收的写组完成，再复位 writer 与写入 FIFO，不复位 SDRAM IP。

## 当前图片和错误约定

支持 `1 <= height <= 480`、`4 <= width <= 640` 且 **width 为 4 的倍数** 的 BMP。小图左上对齐，其余列和行补黑，不缩放。原 writer 负责 BMP 上下方向转换，reader 统一按显示的从上到下顺序读。

本次没有实现四字尾包协议。宽度未对齐、零尺寸、超出显示容量、无效基址或运行中更换缓存池，会报 `load_error_code=8'hE1`。非法描述不送给 writer，也不接受像素；顶层取消 Storage 事务并重新初始化卡，之后可以重新请求有效图片。Storage 原有文件错误代码保留。

## 顶层与 memory 接口

| 信号 | 所属域 | 含义 |
| --- | --- | --- |
| `start && load_ready` | SYS_CLK | 接收一次文件加载请求 |
| `frame_base_addr` | SYS_CLK | 两块缓存组成的缓存池起始字地址，首次加载前配置，后续保持一致 |
| `load_done` | SYS_CLK | Storage 成功交完源数据 |
| `memory_frame_write_done` | SYS_CLK | writer 完成并排空；保持电平，新帧描述会清零 |
| `frame_write_ready` | SYS_CLK，memory 内部接口 | 后台槽可接收新帧，描述 CDC 和清理通路均就绪 |
| `display_ready` | 像素时钟 | 已有有效前台帧；并非某张新图已经显示完 |
| `display_underflow` | 像素时钟 | 本帧 FIFO 欠载或读响应超时，下个消隐刷新点尝试恢复 |
| `HDMI_CLK_P`、`HDMI_D[2:0]_P` | 串行输出 | 新增的 HDMI 输出端口，板级管脚仍需约束核定 |

`memory_top` 新增 `display_clk/reset_n/frame_sync/pixel_req` 输入，以及 RGB、valid、ready、underflow 输出；写入侧继续采用 RGB888 的 valid / ready 和一次帧描述。多位帧描述经过原有保持总线 / toggle 握手跨域；显示消隐电平、后台槽位和状态经过同步器。后台可写状态在 memory 域先寄存，消除状态交接毛刺；其控制域同步链比后台槽号多一级，确保槽号稳定后才允许新请求。

## 仲裁、FIFO 和复位

- 仲裁器只在 SDRAM 空闲时发放新组授权，获得授权后必须连续提交四拍。整组读、整组写不交错，等待 IP 忙状态和返回数据排空后才释放端口。
- 刷新请求到来后禁止新组，已开始的组完成；继续使用原 15 us 刷新调度及看门狗。
- 通用异步 FIFO 增加只读的 `wr_used` 端口：用写指针减去同步后的 Gray 读指针，得到写域保守水位。已有 FIFO 接口的收发行为不变。
- 显示 FIFO 水位不超过一半时优先补读，其余时候读写轮流。后台持续写入接受反压，不能抢占一半带宽而使前台读饿死。
- 输出队列自行预取两个像素，覆盖异步 FIFO 的寄存读延迟。欠载后本帧后续像素输出黑色，下一次消隐统一丢弃旧队列并从坐标 0 重启，防止晚到像素整体错位。
- reader 的响应超时为 256 个 memory 时钟周期。晚到的旧数据先排空，下一消隐重新开始；IP 如果永久 busy，仍需外部复位，不能把该机制理解为所有硬件故障都能自动恢复。
- 外部复位使帧缓存有效位、CDC、writer、reader、两个 FIFO 和显示状态失效；各域同步释放。FIFO 清空指针，SDRAM 内容不物理清零。

## 验证结论与边界

可重复测试位于 `verification/display_memory_20261028`。详细命令、结果和源文件指纹在本次 FFF 验证记录中，项目内摘要见该目录 README。

已通过应用接口模型下的 14 帧功能检查、完整 640×480 三帧逐像素检查、实际 Storage / SPI 卡 / HDMI 链路测试，以及 TD 33 个混合语言源码的层级展开和 gate 综合。覆盖双缓冲、后台并发写、补黑、方向、同高度帧、前台保护、取消、非法宽度恢复、欠载、读超时、复位和刷新。

**厂商 IP 的正式相位读回仍有已知限制。** 当前 125 MHz / 180° 与参考 SDRAM 器件模型组合，在短帧诊断中 512 个显示像素出现 32 个 Z，均为每组第四字。测试台 270° 诊断下同样 512 像素全部正确；这个相位只用于测试，没有改工程 PLL。不能将诊断通过写成当前相位已经修复或板上显示已通过。

完整真实 IP 的 640×480 长跑在 600 秒工具时限前已核对两帧、614400 像素且未发现错误，但没有到达最终 PASS 标志，因此单独记为未完成。另行完成真实 IP 的 640×16 连续长行诊断：3 帧、30720 像素、424 次刷新和后台并发写入均通过，仍仅使用测试台 270° 相位，不替代正式相位验证。

TD 综合确认显示 FIFO 使用 6 块 BRAM9K，整个系统使用 2 个 PLL；本次未做布局布线、板级管脚与跨域时序签核、HDMI 电气测试或上板验收。综合中的 SDRAM 读寄存器时钟警告已追踪到最终 PAD 网表：32 个 DQ 输入寄存器的 `ipclk` 均连接 memory `Clk`；保留原始日志，不将警告静默丢弃。
