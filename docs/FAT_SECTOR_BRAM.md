## 代码改动

生产RTL只改 `rtl/storage/fat32_bmp_reader.v`：

- 512×8位 sector 由组合读取改为无复位的同步读写RAM；实际综合确认映射为每实例1块BRAM9K。
- 增加 CACHE_PRIME 预取状态，完整扇区接收后、目录项跳转后先准备首字节。
- 目录项/FAT链按下一地址预取；文件流只在实际传输时提前读下一个字节，背压时保持当前字节和last。
- 每次扇区/目录项切换多一个准备时钟；扇区内部仍可连续每拍输出1字节，没有降为两拍一字节。
- 保留小型元数据缓存、MBR/BPB合法性/范围/溢出检查、碎片链、末图查找、文件参数、接口和错误码；没有共享或删减两套文件上下文。

PLL、SDRAM IP/读写/刷新控制、FIFO、ADC/SDC、图片/音频解码、字幕/频谱和顶层逻辑均保持原字节内容。不要把本次净省1150理解为已完成公共FAT服务重构。

## 验证结果

| 测试 | 结果 |
|---|---|
| 原版基线 MBR/SD SPI | FAT18场景、引脚级6场景通过 |
| BRAM版原有 MBR/SD SPI | 相同18+6场景通过，含合法MBR碰撞和错误恢复 |
| 新增缓存公共接口测试 | 原版和BRAM版各23场景、22845个输出字节比较通过 |
| 文件流边界 | 长度1/511/512/513/1023/1024/1250，跨扇区/碎片簇链、第二目录簇、末图查询通过 |
| 背压/吞吐 | 全速、交替、随机背压；0/1/510/511/512/1023/1249字节处长停顿通过；连续扇区内传输间隔严格1拍 |
| 复位/异常 | 接收中、511字节背压中复位并用不同数据重新覆盖；CRC/短扇区失败及恢复通过 |
| WAV与HDMI | WAV10场景、SPI真实播放5000采样、HDMI4796采样、板级控制、核心两图并发通过 |
| 字幕/频谱整机 | 两图、19294音频CDC采样、17947有效采样、10个循环、32次频谱更新通过 |
| 多图/轮播 | 六图0→1→2→3→4→5→0及停止后手动切图，8次图片字幕绑定、10300805个渐变像素通过 |
| TD最终端点 | 新版24886项唯一检查，负余量0，含64项DQ输入、64项DQ输出 |

系统测试使用实际Storage/SD SPI/WAV/HDMI及应用层SDRAM模型；本轮未重新运行真实SDRAM器件模型的长回归。SDRAM生产代码和约束未变，物理DQ时序已重新检查。既有封装SDRAM位置和两条时钟局部布线提示仍留档，未宣称零警告。系统ModelSim保留此前未连接wr_used输出的两条提示，本次不顺带修改无关memory代码。
